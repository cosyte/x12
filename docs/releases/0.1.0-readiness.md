## Break candidates

A break candidate is a change a pending changeset makes to a name that was
ALREADY exported at 0.0.18, where a caller written against 0.0.18 could stop
compiling or stop agreeing with the package. A new exported name is not a break
candidate: it breaks nobody. Nor is a row added to a frozen data export whose
stated contract is additions-only, which is what `ALL_WARNING_MESSAGES` and
`X12_TR3_CONFORMANCE` are.

Measured rather than asserted: no name exported at 0.0.18 is removed or renamed
at this commit. The three rows below are all of the remaining kind, a required
member added to a public type. Each binds only a caller that CONSTRUCTS one of
these shapes itself; every caller that reads what the library returns is
unaffected, which is why each is accepted rather than deferred. The disposition
column is the record the release run reads before it bumps.

## Release notes

Every audited changeset appears under exactly one heading, `Features` for the
`minor` rows and `Fixes` for the `patch` rows, and no note appears that no
audited changeset produced.

### Features

- `code-list-redistribution-per-list`: every bundled code list now publishes who maintains it, whether its descriptions may be redistributed, and whether it is the complete published list or a cited part of one.
- `code-list-validity-dates`: the bundled CARC and RARC snapshots carry the maintainer's per-code dates, and two new queries answer whether a code was valid on the day a document was produced.
- `eligibility-270-typed-model`: typed read and emit support for the 270 eligibility benefit inquiry, with the hierarchy nested as the sender transmitted it and a spine the builder computes.
- `eligibility-271-aaa-request-validation`: a payer's request-validation rejection is now typed onto the 271 model, so a rejected inquiry no longer reads as a member with no benefits.
- `profiles-conformance-and-emit-independence`: every described trading-partner quirk carries a conformance classification, and the emit path's independence from profiles is an enforced invariant.
- `status-276-typed-model`: typed read and emit support for the 276 claim status request, closing the second half of the inquiry direction.
- `tr3-conformance-manifest`: a new export states which implementation guide the library implements for each transaction it reads or builds, and how that identifier stands against the federal incorporation by reference.

### Fixes

- `package-description-names-both-halves`: the package description names the emit half beside the read half and states the healthcare scope it covers, so the registry listing no longer describes a read-only library.
- `phi-scan-refuses-an-unread-target`: the PHI scanner no longer reports on a corpus it did not finish reading. A run that withdrew a target it had enumerated used to report on the rest and say nothing about the one it skipped; it now prints the hits it found and then refuses.
- `readme-house-standard`: the package page is rewritten to the house standard, its usage example is executed on every test run, and it is pinned to the manifest by a drift check.
