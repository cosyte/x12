# scripts/phi-allow-list.txt
#
# PHI-scan allow-list, the positive declaration that a fixture's identifiers
# are synthetic. `scripts/phi-scan.ts` reads this file; any realistic-PHI-shaped
# token NOT covered here is a hit. X12 `.edi` files cannot carry an inline
# `# synthetic: true` header (the ISA segment must start at byte 0), so this
# allow-list is the synthetic-fixture declaration mechanism, the same approach
# `@cosyte/dicom` uses for binary `.dcm` files.
#
# Format: `<TAG> <value>` per line. `#` comments and blank lines are ignored.
#   NAME <token>         synthetic person/contact-name word (NM1 / PER name elements), case-insensitive
#   DOB <CCYYMMDD>       synthetic date of birth (DMG*D8), exempt from the date-of-service cutoff
#   ID <value>           synthetic id: an SSN/EIN/NPI 9-or-10-digit shape, OR an NM1 member id
#   EMAILDOMAIN <domain> reserved/test email domain that is allowed to appear
#
# To add a new synthetic fixture: reuse the tokens below, or append new ones here
# and commit. Adding a token is a reviewed, intentional act, never silent.
#
# AN ENTRY HERE IS GLOBAL AND ROUTE-BLIND, AND THAT IS THE COST OF EVERY LINE IN
# THIS FILE. It clears that literal for the whole-tree sweep, for `phi-scan
# <path>`, AND for `pnpm phi-scan --staged`, which is the commit-blocking
# pre-commit gate. So a NAME token added here is a surname the gate will never
# flag again, on any route, in any file. That is why the tokens below are
# placeholders nobody is called rather than plausible names, and why the fix for
# a plausible one is to change the fixture instead of declaring it.
