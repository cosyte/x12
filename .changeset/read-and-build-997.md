Read and build the 997 Functional Acknowledgment with `parse997` and `build997`, for trading partners that still answer with a 997 instead of a 999. The 997 is read and written to the ASC X12 base standard alone: no implementation guide names it, so `parse997` checks no declared guide, and `build997` writes GS-01 `FA`, GS-08 `005010` and an ST with no ST-03. AK1, AK2, AK3, AK4, AK5 and AK9 are read and written by the same code as the 999's, with every refusal `build999` applies. AK5-01 and AK9-01 are typed (`X12Ack997SetDispositionCode`, code list 717, and `X12AckDispositionCode`, code list 715); every other code is carried as sent. Unlike `parse999`, the 997 reader fills nothing in: an absent AK1, AK5 or AK9 reads as `undefined`, and a disposition outside its list reads as an `undefined` `disposition` beside `dispositionRaw`, the code as sent, so test for an accept rather than for a reject. Six warning codes are added for those cases, `X12_997_AK1_ABSENT`, `X12_997_AK5_ABSENT`, `X12_997_AK9_ABSENT`, `X12_997_AK5_DISPOSITION_UNKNOWN`, `X12_997_AK9_DISPOSITION_UNKNOWN` and `X12_997_SEGMENT_OUT_OF_PLACE`, each with a factory of the same name pattern (`ack997Ak1Absent` and the rest). New exports: `parse997`, `build997`, `X12_997_SET_DISPOSITION_CODES`, the six factories, and the types `X12Ack997`, `X12Ack997Ak3`, `X12Ack997Ak4`, `X12Ack997Ak5`, `X12Ack997Ak9`, `X12Ack997SegmentNote`, `X12Ack997TransactionResponse`, `X12Ack997SetDispositionCode`, `Build997Spec`, `Build997FunctionalGroupSpec`, `Build997TransactionResponseSpec`, `Build997SegmentErrorSpec` and `Build997ElementErrorSpec`. `X12_TR3_CONFORMANCE` gains a 997 row with no guide identifier (`tr3: null`, not adopted), and `@cosyte/x12/arbitraries` gains the 997's GS-01 `FA`. One change to `build999` you can see only from JavaScript: an IK3-04 or IK4-03 holding a delimiter is now released rather than written raw, so it no longer shifts the elements after it, and a non-string one is refused with the escaper's message; every 999 built from a typed spec is byte for byte the same. Nothing you call needs to change.
