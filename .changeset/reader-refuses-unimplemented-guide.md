A typed reader now returns no reading for a transaction set that declares an implementation guide it does not implement, such as a 4010 document, instead of reading it against the 005010 element positions with an `X12_GUIDE_NOT_IMPLEMENTED` warning. This is a behaviour change. `get835`, `get837Claims`, `get270Inquiry`, `get271Eligibility`, `get276StatusInquiry`, `get277Status`, `get278Request`, `get278Response`, `get820Payments` and `get834Header` return `undefined` for it, `get834Enrollments` yields nothing, and `parse270Inquiries` and `parse276StatusInquiries` leave it out of the list, exactly as each already does for a transaction set of another ST-01. The declared guide is ST-03, else GS-08, and the guides each reader implements are its rows of `X12_TR3_CONFORMANCE`. The decision to refuse compares the declaration trimmed of surrounding whitespace and upper-cased, so a 005010 guide declared with padding or in lower case (`005010X222A1` with a space either side, or `005010x221a1`) is still read, with the `X12_GUIDE_NOT_IMPLEMENTED` it carried before. A 4010 277U (`004010X070`) now gets `undefined` from `get277Status` where it got a reading labelled `transactionType: "unrecognized-guide"`, and so does a 277 declaring `006020X313`; the label is now given only to a 277 that declares no guide, or an implemented one padded or in another case. A 278 declaring `005010X216`, the notification guide, gets `undefined` from both 278 readers. A transaction set that declares no guide at all is still read, with `X12_GUIDE_NOT_DECLARED`, and a declaration of whitespace alone now counts as none: an ST-03 of whitespace falls through to GS-08, where it was warned `X12_GUIDE_NOT_IMPLEMENTED`, and a GS-08 of whitespace declares nothing. What a caller must change: a caller that read such documents and filtered on `X12_GUIDE_NOT_IMPLEMENTED` gets `undefined` now and can drop that filter; a caller that relied on reading them must translate them to a 005010 guide first, or, where it knows a document follows an implemented guide despite its declaration, hand the reader a copy of the transaction set whose ST-03 names that guide. A refused transaction set carries no warning, because there is no reading; `X12_PRE_005010` on the interchange is the one sign for a 4010 document. `get275Attachments` and `parse999` still warn and return for every guide they do not implement. KNOWN-LIMITATIONS now names the 4010 variants and the 4010 277U as not built.
