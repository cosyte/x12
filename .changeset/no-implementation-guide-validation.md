The README, KNOWN-LIMITATIONS and the troubleshooting page now state plainly that this package does not validate a document against its implementation guide (TR3). It checks the ASC X12 base standard, the few guide facts each typed reader needs to build its model, one CAQH CORE rule (the CORE 360 Code Combinations, through `checkCoreCodeCombination` with a table you supply), and codes against the lists it bundles (the `X12_UNKNOWN_CARC`, `X12_UNKNOWN_RARC`, `X12_UNKNOWN_CLAIM_STATUS`, `X12_UNKNOWN_CLAIM_STATUS_CATEGORY`, `X12_271_AAA_UNKNOWN_CODE`, `X12_UNKNOWN_HI_QUALIFIER` and `X12_834_UNKNOWN_MAINTENANCE_TYPE` warnings, and the `build834` refusal `X12_834_BUILD_UNKNOWN_MAINTENANCE_TYPE`). Three of those lists, `MAINTENANCE_TYPE_CODES`, `CLP_STATUS` and `HI_QUALIFIERS`, are code subsets cited from a TR3; we ship no TR3 usage tables and do not check TR3 usage, such as required, situational and not-used segments and elements, repeat counts, or code values beyond the bundled lists. The pages also list what you can check yourself with the typed readers. Nothing you call changes.
