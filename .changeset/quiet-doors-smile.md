The PHI commit-gate now opens every tracked file under `test/`, and reads X12 segment text that a `.ts` string literal is holding.

**No library surface changes.** This is `scripts/phi-scan.ts`, the repository's own PHI gate. It is called out in a changelog because the gate is what stands between a real-looking X12 fixture and a public commit, and because two of the changes below alter what the pre-commit hook refuses.

**Enumeration.** The walk roots move from `test/fixtures` + `src` to `test` + `src`, and the `--staged` clauses from `test/fixtures/**` plus `src/**.ts` to `test/**` plus `src/**`. Both are unions: the old scope is a subtree of the new one, so no path either route enumerated stops being enumerated. Derive the census with `git ls-files` rather than trusting a number: at the parent commit the tracked files under `test/` outside `test/fixtures/` were opened by **neither** route, which in an EDI package is where the inline fixture corpus lives.

**Recognition, and it is the half that mattered more.** `looksLikeX12` asks whether the _file is_ an interchange - it must start with `ISA` and be at least 106 bytes - so a `.ts` file holding an `NM1` person-name segment went down the plain-text branch, where only the three unanchored shape checks ran (dashed SSN, the `REF*SY` undashed nine-digit SSN, a non-test email) and the NM1 name, NM1 member-id, NM1 NPI, PER contact-name, PER communication-number, DMG date-of-birth and pre-2024 service-date recognisers ran not at all. `scanEmbeddedSegments` closes that: it finds a known segment id followed by `*`, takes the run to the first segment terminator, double quote, backtick, backslash or newline, removes `${...}` so an interpolated fixture keeps its element positions, and hands the result to the same checks. **It is in addition to the shape pass, never instead of it.**

**The new pass is a syntactic tripwire over source text, not a parser, and what it cannot see is deliberately not published as a closed list.** A draft of this entry said "four bounds" and a reviewer found two more in one pass. Measured and pinned: it assumes `*` as the element separator, because an embedded run has no ISA to declare one; it recognises only the segment ids the checks consume; it does not run on a whole-file interchange, which would report every hit twice; the bytes inside a `${...}` placeholder are removed before the split, so a name an interpolation holds is never checked; a segment split across a concatenation is not reached; a run ends at the first `"`, backtick, terminator, backslash or newline, so every element after one of those ceases to exist; and it skips a name element or an id element that its shape predicate rejects. **Those last narrowings apply to the embedded pass only; the whole-file `.edi` path is unchanged, asserted with the same bytes on both sides.** A fixture written as a builder spec object rather than as segment text is reached by nothing, which was found by hand-reading and is pinned so the silence is not read as coverage.

**Two element-shape decisions are worth stating outright, because a draft had both backwards in the leak-hiding direction.** An apostrophe is **not** a run stop. While it was one, by symmetry with the double quote, every embedded run was truncated at the first apostrophe: an `NM1` person name of the `O'Brien` shape in a `.ts` literal reported clean, and so did whatever followed the apostrophe in that segment: an `MI` member id in one measured case, a qualifier-34 SSN in another, and a non-555 phone in the `PER` equivalent. The `scanCommonShapes` floor covers neither the member id nor the qualifier-34 SSN. Taking the apostrophe out has its own price, disclosed with the rest: a run inside a **single-quoted** literal now overruns that literal's closing delimiter, so a single-quoted fixture whose id is its final element is skipped. And "letter" means `\p{L}` rather than `[A-Za-z]`, so a name element carrying a tilde-n or an acute accent is no longer skipped outright. **That buys only elements in which an ASCII letter still survives token filtering**: a token with no ASCII letter in it at all is dropped elsewhere, on both routes, identically to how it behaved before this change.

**One cell of the widening was not additive, and a base/head grid is what found it.** `refuseUnusableRoots` iterated the walk roots, so while `test/fixtures` was one, deleting it refused at exit 2. Making `test` the root turned `test/fixtures` into an ordinary subdirectory, and on a tree whose corpus was not yet committed the same deletion read `OK - no hits` at **exit 0**. `REQUIRED_DIRECTORIES` is the fix: what must _be_ a directory is now declared separately from what the sweep walks, because the walk roots must stay disjoint and that list need not.

**What the pre-commit hook refuses widens, and no count of the ways is published, because a draft published one and it was short.** A violator staged directly under `test/` is now scanned where it was not, and so is a non-`.ts` file staged under `src/`. So is a path that was already in scope at base but is not itself an interchange, because the route gains the segment-aware pass along with the other two. **No exemption was added on any route**, deliberately.

**Sixteen allow-list entries were added, and an allow-list entry is global and route-blind.** Twelve `NAME` tokens and four `ID` values, every one a placeholder from an inline fixture, hand-read before declaring. Each clears that literal on the commit-blocking route as well as the sweep, which is the cost, and tests pin it from both directions: a declared value passes on `--staged`, an undeclared sibling of the same shape does not. `isSyntheticMemberId` now consults declared ids, which flips no result the scanner already reported, because every `ID` entry predating the change is all-digit and already matched an existing shape.

**Every file the widening opened was hand-read. Nothing patient-identifying was found.** The corpus is placeholders throughout. Non-patient, publicly attributable strings are named in `documentation/agent-notes/phi-scan-walk-root-scope.md` rather than scrubbed: the NDC labeler codes in the drug-identification fixtures, the CMS test NPI, and the `example.com` git identity a throwaway test repository commits under. Every PHI-shaped value in the gate's own test file is invented for a detector to trip on, and assembling the controls puts all of them out of the gate's view; that is stated there as a rule rather than as a list, because a list of them went stale inside one commit.

**The gate's own negative controls are now assembled element by element rather than written as literal segment text.** Those payloads must trip the scanner - that is what they are for - so declaring them would disarm the detector each one proves, and a literal-path exemption would have to reach `--staged` or the file could never be committed again. The values stay legible in the source; only the framing is built at run time.
