A segment whose first element is empty (`*A*B~`) outside a transaction set is now warned, kept and re-emitted, where `parseX12` used to skip it with no warning, losing its values from the model and from `serializeX12`. This is a behaviour change. Such a segment now raises `X12_UNEXPECTED_SEGMENT` with the existing body-outside-a-transaction message, is kept on `ix.orphanSegments` with context `body-outside-transaction`, its anchor, its raw text and an empty `segment.id`, and `serializeX12` writes it back at that anchor, so it round-trips byte for byte. No warning code is added. What a caller must change: `parseX12(raw, { strict: true })` now refuses such a document with an `X12ParseError` carrying `X12_UNEXPECTED_SEGMENT`, as it refuses every other segment outside a transaction, so a strict caller that accepted one before must handle that error; a lenient caller that requires an empty `ix.warnings` will now see the warning, and a caller that reads `orphanSegments` should not assume a non-empty `segment.id`. A segment with an empty first element inside a transaction set was always kept and is unchanged, and a doubled segment terminator still delimits nothing and stays silent. KNOWN-LIMITATIONS drops it from the round-trip list, which now has five constructs.
