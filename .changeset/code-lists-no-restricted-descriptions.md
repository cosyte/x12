The bundled code lists now ship description text only where the list's own redistribution record says `permitted`, which today is the Remittance Advice Remark Codes alone; every other list keeps its codes and returns no description. This is a behaviour change. `CARC`, `CLAIM_STATUS_CATEGORY_CODES`, `CLAIM_STATUS_CODES`, `SERVICE_TYPE_CODES`, `CLP_STATUS` and `MAINTENANCE_TYPE_CODES` keep every code, their `meta` and, for CARC, the per-code dates, and map each code to `undefined`, because the package's own record classes these lists as `licence-required` or `not-established`. Their lookups still return an entry for a bundled code, now with `description: undefined`, so every unknown-code warning and the `build834` refusal fire exactly where they did. The read models carry `undefined` in `reasonDescription` (835 and 837 adjustments), `claimStatusDescription` (835 claims), `categoryDescription` and `statusDescription` (277 and 277 RFAI), `description` on 270 and 271 service types, and `maintenanceTypeDescription` (834), and `checkCarcValidity` returns the same verdicts with `description: undefined`. Types: `CodeListEntry.description` is now `string | undefined`, `CodeListSnapshot.codes` is `Readonly<Record<string, string | undefined>>`, and every `lookup*` helper takes an optional second argument, the new exported `CodeListLookupOptions`. What a caller must change: a caller that displayed these descriptions now gets `undefined`, and can pass its own table as `lookupCarc(code, { descriptions: yourTable })` (and the same on every other lookup), which answers a bundled code with your text and a code outside the bundled subset with `{ code, description }` from your table; `examples/describe-codes-with-your-own-table.ts` shows it with made-up text. A caller that tested whether a code is bundled with `CARC.codes[code] !== undefined` must use `Object.hasOwn(CARC.codes, code)` or the lookup instead. `pnpm refresh:code-lists` now fails a list not recorded as `permitted` that carries a description. The `HI_QUALIFIERS` descriptions are rewritten as our own note of what the library does with each qualifier, the Claim Adjustment Group Code and acknowledgment code comments carry the code values with that note in place of definitions, and comments that cited implementation-guide sections now say no guide was read. RARC is unchanged.
