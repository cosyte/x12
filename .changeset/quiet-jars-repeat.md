`KNOWN-LIMITATIONS.md` now ships inside the published package, and the self-contradiction it carried about an 837 segment following a stray `LX` is resolved by deleting the false half (`X12-837-LOOP-RESIDUALS`).

**The document is in the tarball because the library's own runtime output cites it.** `X12_837_SERVICE_LINE_DROPPED` and `X12_837_ENTITY_SEGMENT_DISCARDED_AFTER_LX` both carry "see KNOWN-LIMITATIONS.md" one clause before they close, but the document was absent from `package.json`'s `files`. An installed copy therefore carried a warning naming a document that was not beside it. Of the two ways to close that, the citation is the one worth keeping: the document is the canonical account of what this reader does not reproduce, and someone holding a code, a `position` and a message is exactly the reader who needs it. So the packaging moved and the messages did not.

**Name the cost rather than only the benefit.** A file in the tarball is a published artifact, permanent at the version that carries it, so every claim in that document is now held to the bar a published surface is held to. That is a real raise, and it is accepted on the ground above rather than argued away. The line is drawn at what the library says to a caller **at runtime**, and only that: `docs-content/` is referenced from prose and JSDoc but never from a message you see, so it is deliberately still not in `files`, and the shipped `README.md`'s relative links to `./docs-content/cookbook.md` and `./docs-content/troubleshooting.md` still do not resolve inside an install. That is pre-existing, unchanged here, and is its own decision.

`test/package-files-cite.test.ts` refuses a shipped warning message that names a repo-root `.md` file `files` does not carry, and separately asserts the cited file is on disk, so a `files` entry naming nothing cannot satisfy it. It reads the exported warning registry and nothing else: not JSDoc, not source comments, and not the `build*` refusal templates, none of which a consumer sees at runtime.

**The false statement.** "The trailing segments were filed against it", "they attached to whichever party the last `NM1` left active", and the counterfactual carried by "no longer attaches itself to the last named party" all read as all four of `N3` / `N4` / `PER` / `REF` having reached every party through `0.0.10`. They did not: `attachContact` has no route for a patient or a pay-to address and `attachReference` none for a pay-to address, so those segments reached no party on any release. That is why the warning code added alongside reports that a segment reached **no** party and never that it would otherwise have reached one. `KNOWN-LIMITATIONS.md` additionally carried, ninety lines from the entry contradicting it, a fourth wording of the same universal in the present tense: "a `NM1` arriving AFTER that `LX` names a party normally, and its own trailing segments attach". That parenthetical is deleted, not given a fifth wording. What a party named after such an `LX` does is unchanged, and that code's own entry still states its scope and says outright that whether a later party's trailing segments attach is a separate question it does not answer. No per-kind, per-party map is published in the documents this package ships, deliberately. The same wording survives in `src/` comments and in test-file headers, neither of which this change swept or fixed.

**Nothing about the parser changed.** No code, no type, no warning code, no warning message, and no model shape. The measured instances each corrected statement rested on are unchanged and stay, and every one of them is on a **payer**, which does surface an address, a reference and a contact: a line-item control number in a later claim's `payer.references`, a street address in `payer.address`, and a contact in `payer.contacts`, none of which the sender put there.
